# راهنمای استقرار روی cPanel (فارسی)

> وضعیت: این راهنما بر اساس بررسی کد نوشته شده است. **روی هاست واقعی cPanel تست نشده است.** پس از هر مرحله، نتیجه را با ابزار `setup_check.php` و آزمایش‌های دستی انتهای همین سند بسنجید.

## ۱) پیش‌نیازهای هاست
- PHP نسخه **۸٫۱ یا بالاتر** (در cPanel: *Select PHP Version* یا *MultiPHP Manager*). نسخه‌های ۷٫x و ۸٫۰ کار نمی‌کنند (کد از نوع بازگشتی `never` استفاده می‌کند).
- افزونه‌های فعال: `pdo_mysql`، `mbstring`، `fileinfo`، `ctype`، `json`، `session`، `filter`.
- وب‌سرور Apache یا LiteSpeed با پشتیبانی از `.htaccess` (`mod_rewrite`؛ `mod_deflate` و `mod_expires` اختیاری‌اند). اگر هاست فقط Nginx است، قوانین `.htaccess` اجرا نمی‌شوند و باید معادل آن‌ها در تنظیمات Nginx نوشته شود.
- **این پروژه از MySQL/MariaDB استفاده می‌کند.** پیش از شروع، دیتابیس و کاربر آن را در cPanel بسازید و فایل‌های SQL را import کنید؛ راهنمای کامل: `docs/MYSQL_CPANEL_FA.md`.

## ۲) بارگذاری فایل‌ها
1. از ZIP پروژه، **محتوای پوشه** `borj_afraz_almas_pardis_site` را در `public_html` (یا پوشه‌ی ساب‌دامین) آپلود و Extract کنید. (از *File Manager*، یا FTP/SFTP.)
2. اطمینان حاصل کنید فایل **`.htaccess`** هم آپلود شده است (در File Manager گزینه *Show Hidden Files* را فعال کنید).
3. دسترسی‌ها: پوشه‌ها `755`، فایل‌ها `644`. پوشه‌های `data/` و `uploads/` باید برای کاربر PHP قابل نوشتن باشند (روی اکثر هاست‌های cPanel با `755` و مالکیت حساب خودتان کافی است؛ `777` را **نگذارید**).

## ۳) تنظیم مدیر (private_config.php)
1. بهتر است پوشه‌ای **بیرون** از `public_html` بسازید، مثلاً `/home/نام‌کاربری/borj_afraz_private/`.
2. فایل `private_config.example.php` را در آن پوشه با نام `private_config.php` کپی کنید (پروژه این مسیر را به‌صورت خودکار می‌خواند: `../borj_afraz_private/private_config.php` نسبت به پوشه‌ی سایت).
3. مقادیر را تغییر دهید:
   - `ADMIN_USERNAME`: نام کاربری دلخواه (نه `admin`).
   - `ADMIN_PASSWORD_HASH`: هش رمز قوی. در *Terminal* cPanel یا هر PHP: `php -r "echo password_hash('رمز-قوی', PASSWORD_DEFAULT), PHP_EOL;"`
   - `SITE_PHONE`: شماره‌ی واقعی شرکت.
4. اطلاعات اتصال MySQL را در همین فایل (`DB_HOST`، `DB_NAME`، `DB_USER`، `DB_PASS`) وارد کنید.

## ۴) مهاجرت دیتابیس
- **کار دستی لازم نیست.** اولین درخواست به هر `api/*.php` ستون‌ها و جدول‌های جدید را داخل یک تراکنش می‌سازد (فقط یک‌بار؛ نسخه‌ی اسکیما با `PRAGMA user_version` نگهداری می‌شود).
- اگر از نسخه‌ی قبلی ارتقا می‌دهید: **قبل از هر کاری** از دیتابیس (phpMyAdmin ← Export) و پوشه‌ی `uploads/` پشتیبان بگیرید.
- مهاجرت دستی (اختیاری): `migrations/001_building_specs.sql`.
- بازگشت: سایت را موقتاً ببندید، دیتابیس را از نسخه‌ی پشتیبان Import و فایل‌های قدیمی را برگردانید.

## ۵) بررسی محیط با setup_check.php
1. در `private_config.php` یک کلید تصادفی تعریف کنید: `define('SETUP_CHECK_KEY', 'یک-رشته-تصادفی-حداقل-۱۶-نویسه');`
2. در مرورگر باز کنید: `https://YOUR-DOMAIN.ir/setup_check.php?key=کلید`
3. خروجی باید برای موارد ضروری `[OK]` باشد. هر `[FAIL]` را برطرف کنید؛ `[WARN]` را بررسی کنید.
4. **بلافاصله بعد از بررسی، `setup_check.php` را حذف کنید** و کلید را از `private_config.php` بردارید.
> این ابزار هم روی هاست واقعی تست نشده است؛ اگر خودش خطا داد، متن خطا را برای بررسی بفرستید.

## ۷) تنظیمات PHP پیشنهادی (MultiPHP INI Editor)
`upload_max_filesize = 6M`، `post_max_size = 64M`، `display_errors = Off`، `max_execution_time = 60`.

## ۸) پس از استقرار
- پشتیبان‌گیری منظم از دیتابیس MySQL و `uploads/` (cPanel → *Backup* یا Cron).
- رمز مدیر را در مدیر رمز نگه دارید؛ در صورت لو رفتن، هش جدید بسازید.
- اگر پشت Cloudflare هستید: محدودیت تلاش ورود بر اساس IP است و همه‌ی کاربران ممکن است یک IP ببینند (مدیر ممکن است توسط یک مهاجم قفل شود). یا Cloudflare را روی «DNS only» بگذارید یا برای تنظیم IP واقعی با پشتیبانی هماهنگ کنید.
